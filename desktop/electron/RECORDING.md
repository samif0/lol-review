# Automatic match recording

Revu bundles OBS 32.2.2's recording engine in a separate `revu-recorder.exe` process. Electron controls its lifetime through a bounded JSON-lines pipe; native graphics/audio code never loads in the renderer, Electron main process or database-owning sidecar. The normal build still declares no Overwolf gaming packages and needs no Recorder developer access.

## Setup and scope

From `desktop`, run `npm run recorder:setup` to acquire the pinned OBS runtime and build the x64 helper. The setup needs Visual Studio C++ Build Tools and the Windows SDK. Downloads and output remain in ignored `artifacts/`; `npm run package:dir` includes the verified runtime under the app's `recorder/` folder. `npm run recorder:probe` checks the installed modules and eligible hardware H.264 encoder without recording a window. The recorder's own README describes distribution and source requirements.

Settings → Recording shows beta controls when the host can initialize the bundled helper. Recording is off by default; a saved opt-in from the former development provider is cleared once when switching to libobs. Enable it before starting a Ranked Solo/Duo match (queue 420), use League's Borderless mode, and keep Revu running. Only observed `GameStart`, `InProgress` or `Reconnect` phases trigger native process discovery. There is no WMI/PowerShell polling in this provider.

The helper detects the active recording graphics adapter and automatically selects its eligible NVIDIA NVENC, AMD AMF or Intel Quick Sync H.264 texture encoder. Settings shows the selected encoder and the encoder used by the last recording. A compatible GPU and installed vendor driver are required; registration alone does not prove recording initialization will succeed. Selection excludes encoders on other adapters and CPU software encoding. OBS's vendor plugins can internally use a frame readback path while retaining hardware compression; their public encoder ID still names the original selected entry. Revu does not switch or restart engines during a recording. Unsupported hardware reports unavailable.

Recording uses explicit WGC Window Capture, League-only process audio, hardware H.264, AAC stereo 48 kHz, and MP4 that is fragmented while recording. A clean stop finalizes it in place to a normal indexed MP4 that players open without walking every fragment, and the host flushes it to disk before linking it. An interrupted file keeps the fragmented layout and plays up to its last complete fragment. If a finished file's index never reached the disk, validation and the next start restore that fragmented layout. There is no remux step. It never selects OBS Game Capture, desktop capture, microphone sources or software encoding. The capture bundle excludes injection helpers and graphics hook DLLs. A minimized window does not establish process exit. WGC can still affect presentation/cursor behavior; its real gameplay cost requires measurement.

## Ownership and recovery

The game always comes first. By default the helper runs at below-normal CPU and GPU scheduling priority, so League gets the processor and graphics card before the recorder. Settings → Recording priority offers "Same as the game" (normal) only to compare recording smoothness; nothing runs above the game. The helper pins the GPU class that libobs raises during startup, opts out of Windows power throttling so its render timer stays accurate, has a bounded memory job, and stops on control-pipe EOF or game process exit. While a recording runs, Electron launches no discovery helpers; the recording helper watches its own game. Each recording's `session.json` keeps its priority and, in `finalStats.perMinute`, the frames, repeated frames and lagged render ticks for every movie minute. Electron waits for process closure on stop and kills an unresponsive helper. Heartbeats indicate helper liveness separately from changing frame counts. A native failure disables provider availability for the current app lifetime and saves recording off so app restart cannot automatically repeat the fault. It never causes an automatic in-game restart or software fallback. These controls contain helper failures, not GPU-driver faults.

Files are stored under `%LOCALAPPDATA%/Revu/Recordings/<session-id>/`. Durable session intent precedes native capture. Interrupted output stays on disk, and host restart marks unfinished sessions partial. Media validation runs only after a clean stop and checks the container layout (an indexed MP4 from the built-in recorder, or a fragmented MP4 from Overwolf), metadata and actual decoded audio/video near the beginning, midpoint and end before registration. A 2 GiB free-space reserve requests a safe stop. Recordings are not automatically pruned: users manage or archive their files through Open recordings folder.

Native `startedAt` derives from an encoded video packet's OBS composition clock and final muxed PTS, calibrated against Windows wall time. It is the movie timeline's origin, not a claim to have measured the WGC source frame's age or full-match semantic A/V alignment. A sampled live game clock maps movie time to match time; playback and clip extraction apply that offset.

Completion requires verified start timing and coverage of fresh exact-match end-clock evidence. Late starts, reconnect segments and interrupted coverage remain partial. The sidecar links a validated partial only when its timing is known and the match has no VOD, exposes `isPartial`, and retains unknown-clock media without attaching it. Existing VOD links are never overwritten. Session IDs make registration retries idempotent; match rows arriving after the video are reconciled by the sidecar.

## External imports and diagnostics

To test actual game capture in Practice Tool, use `npm run start:recording-test` from `desktop`. It opens the local packaged app with a new scratch profile and `--recording-test`; production data cannot be selected for this mode. Enable **Record my test game** in Settings → Recording, then start Practice Tool in Borderless mode. This explicit diagnostic launch accepts an active League test game without the ranked-only queue gate. It does not rely on an undocumented Practice Tool queue number. End the game and open the recordings folder to play the validated test MP4. Test sessions carry a durable marker and are never submitted for match attachment, including after restart.

Ascent folder import remains available. Connecting and scanning its folder links existing videos; disconnecting keeps links and files. Do not move recordings already linked by absolute path. Do not uninstall Ascent on the assumption that a successful helper probe or generated-media test proves live League recording works.

The explicit credentialed Overwolf Recorder development launcher remains a separate diagnostic provider. It is not required by the bundled libobs path. Isolated/smoke launches never probe, discover or start native recording and do not use production data.

## Verification

Desktop tests cover protocol bounds, hardware-only selection and capability consistency, exact queue/phase gating, process closure, crashes, silent helpers, cancellation and unavailable UI states. Native policy tests cover all three GPU vendors, incompatible or unknown adapters, missing hardware encoders, and vendor-specific recording settings. Core/sidecar suites cover queue/session identity, receipts, timed partial linking and keeping existing VODs. Native generated-media diagnostics exercise the detected hardware encoder and the fragmented-then-finalized MP4 without capturing user windows or audio. Policy tests and a successful NVIDIA run do not establish live AMD or Intel recording acceptance.

Still required before recommending Ascent removal: live WGC performance/cursor comparisons, full-match League-only audio and A/V synchronization checks, alt-tab/minimize/reconnect coverage, forced host exit, full-game soaks, and testing additional GPU/driver configurations. Synthetic media and startup checks do not establish those properties.
